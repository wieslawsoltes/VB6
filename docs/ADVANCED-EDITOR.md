# Advanced VB6 and XAML editor

The enhanced code editor is an optional, disabled-by-default presentation over
existing project source, compiler services, debugger and transaction history.
It does not replace the classic editor, project format, runtime or form designer.

## Enable and deploy

Open **Tools > Advanced Editor Options**, select **Enable advanced code editor**,
and apply. Minimap, sticky scope headers, word wrap, ligatures, whitespace,
semantic highlighting, parameter hints and reference CodeLens have individual
options. Cancelling the dialog has no effect. These settings belong to the
browser profile, not the project; unavailable storage affects only persistence.
Only the boolean `enabled: true` enables the feature. Disabling it restores the
classic adapter's source and selection and releases enhanced views and workers.

Build the normal IDE and optional assets with Node 22 or newer:

```sh
npm ci --prefix packages/advanced-editor
npm run build
npm run build:advanced-editor
```

The optional package pins Monaco Editor 0.57.0 and esbuild 0.25.9. It is separate
from the dependency-free normal IDE build. Serve `dist/` over HTTP(S), retaining
`dist/advanced-editor/` beside `index.html`. The hosted IDE fetches no Monaco
assets before opt-in; it does not use a public CDN. GitHub Pages builds and
publishes the optional assets with the existing site.

For a single offline file, use **`dist/VB6-Studio-Web-Advanced.html`**, generated by
the optional build. It embeds the pinned vendor code, stylesheet, fonts and
workers but does not execute the enhanced editor until opt-in. The smaller
`VB6-Studio-Web.html` is still the classic standalone artifact. A missing optional
asset or failed initialization keeps the classic editor usable and reports an
error; reapplying options retries initialization.

`--adapters-only` is a development shortcut for rebuilding adapters against an
already-built matching vendor bundle. It is not a clean build or a substitute for
CI's pinned dependency installation. `dist/advanced-editor/manifest.json` records
output sizes and SHA-256 fingerprints, and the offline payload derives from those
same outputs. The normal IDE retains its separate exact build manifest.

## Editing and navigation

| Area | Implemented presentation |
| --- | --- |
| Source rendering | Virtualized Monaco views; VB6/XAML lexical and semantic colors; minimap; folding; sticky scopes; bracket/indent guides; Unicode and whitespace visualization. |
| Editing | Multiple carets and selections; rectangular selection; snippets with editable placeholders; indentation and commenting; document/selection formatting; find/replace including regular expressions; command palette. |
| Source navigation | Completion and signature help; hover; definition, declaration, type definition and implementation navigation; inline Peek using shared read-only models; references; document outline and project-symbol search. |
| Hierarchies | Modeless call/type tools; incoming/outgoing calls; grouped call-site previews; lazy expansion; cycles; keyboard navigation; virtualized rows; explicit stale-result refresh. |
| Split editor | Two views of one source model with independent selections and scrolling; pointer/keyboard resizing; focus-other-split command; shared undo and debugger/read-only state. |
| Language feedback | Push and negotiated pull diagnostics; semantic tokens; parameter-name inlay hints; reference CodeLens; quick fixes and external refactor/source actions when supplied by a server. |
| Debugger | Breakpoint and execution gutters; bookmarks; existing run/step/watch shortcuts; storage-only paused-frame data tips; existing debugger windows and central edit-and-continue workflow. |
| Designer | XAML source edits and safe workspace edits enter the existing form-designer transaction pipeline; locked/running/invalid edits are rejected without partial application. |

F1 opens the editor command palette, Ctrl+T opens project-symbol search, F12 goes
to a definition, Alt+F12 opens Peek, Shift+F12 shows references, and F2 renames a
safely bound source symbol. Ctrl+K then Ctrl+X inserts a VB6 snippet. Ctrl+Alt+H
opens Call Hierarchy; Ctrl+K then Ctrl+O focuses the other split pane. The View
menu exposes symbol search, call/type hierarchies and the split toggle. Monaco's
Ctrl/Cmd convention applies where supported; browser/OS-reserved shortcuts may
need the corresponding menu action.

Hierarchy rows use Up/Down, Home/End, Right to expand, Left to collapse/go to the
parent, Space to toggle, and Enter to open source. The split separator is keyboard
focusable; Up/Down adjusts it, with Home/End selecting its 20%/80% limits.

## Built-in services versus external servers

Blank language-server URLs use the bundled worker locally. Its VB6 features reuse
`EditorIntelligence`, compiler diagnostics and conditional-compilation indexes;
XAML uses the existing XAML compiler schema and language service. No source is
executed to answer language queries.

VB6 call hierarchy is **statically bound source information**, not a runtime call
trace. It excludes strings, comments, inactive conditional branches, shadowed
locals, `AddressOf` references and function return-variable assignments. It groups
recursive calls and source call sites. Type hierarchy represents VB6 `Implements`
relationships, **not class inheritance**. Interface calls bind to the declared
interface; Go to Implementation locates its source implementation separately.
Dynamic dispatch, COM/native calls and event delivery are not guessed into the
graph. Source graph limits are 20,000 procedures and 100,000 call sites; hierarchy
presentation retains at most 5,000 rows and 32 levels. Narrow/restart a query at a
nested symbol when a limit is reached.

The built-in server provides source-aware completion, hover, signatures,
definitions/references, safe rename, VB6 snippets, symbols, folding, selection
ranges, formatting, semantic tokens, diagnostics and VB6 hints/CodeLens. XAML
includes tag-linked editing and schema-aware navigation/completion. XAML range
formatting deliberately avoids reformatting isolated fragments whose mixed
content or `xml:space` context cannot be preserved. The built-in source action
removes VB6 trailing whitespace; it is not a general refactoring engine.

For an external server, enter its explicit **ws:// or wss://** endpoint separately
for VB6 and XAML. It must exchange one JSON-RPC message per WebSocket text frame,
accept the `vb6`/`xaml` language IDs and project `vb6-editor://` document URIs, and
negotiate UTF-16 positions. An ordinary stdio-only server needs a trusted bridge;
the browser does not spawn arbitrary executables. HTTPS pages require WSS except
for loopback. Embedded URL credentials and fragments are rejected.

The adapter negotiates completion/resolution, signatures, hover, declarations,
definitions/types/implementations, references/highlights, symbols and symbol
resolution, code actions/resolution, CodeLens, document links, colors, formatting
(including on-type where advertised), rename, folding/selection/linked ranges,
semantic full/range/delta results, inlay hints/resolution, call/type hierarchies,
push/pull diagnostics, save notifications, configuration and dynamic provider
registration. Unsupported capabilities are not invented. External actions and
refactorings are only as complete as that configured server's implementation.

**Intentional boundaries:** this is not an implementation of the Visual Studio
extension host, Roslyn/VB.NET language semantics or every Visual Studio command.
LSP filesystem create/rename/delete operations, arbitrary external-document
opening, `willSaveWaitUntil`, workspace-wide pull diagnostics and LSP inline-value
presentation are not advertised. Use the IDE's project/design tools for structural
changes. The existing VM/debugger/native/COM compatibility boundaries remain in
[DEBUGGER-COMPATIBILITY.md](DEBUGGER-COMPATIBILITY.md) and
[COMPATIBILITY.md](COMPATIBILITY.md); this editor does not expand those semantics.

## Source safety and lifecycle

There is one project-owned model per document and one IDE undo history, including
multiple source panes, XAML changes and designer edits. Hidden classic textareas
are adapters, not competing source owners. Mode changes preserve selections;
project replacement, detached-window adoption, connection loss and disposal have
explicit ownership and cleanup. A disconnected language server does not stop
plain editing; reapply options to reconnect. Superseded initialization aborts
pending worker/WebSocket sessions immediately.

Rename and code-action responses capture workspace revisions. Workspace edits
validate document identity/version, edit ranges and overlaps before preparing a
single project transaction, and revalidate the workspace after consent. Unknown
URIs, stale edits, incompatible XAML, locked forms and forbidden run-state edits
fail atomically. Pending IME composition is not overwritten. Markdown is untrusted;
source-only navigation cannot launch arbitrary document URLs. Server commands are
checked against their negotiated allowlist and require explicit confirmation.

Automatic debugger tips use `debugInspect`, not function evaluation. They show
only stored identifiers/field paths in the matching selected paused frame and
source procedure. A changed pause, frame, bridge, source, pending edit or retained
frame invalidates the response. Function calls, call-result members, implicit
With paths and unavailable/property-getter values stay in the existing explicit
debugger tools; automatic hover never calls `debugEvaluate`.

The optional surface contains a narrowly scoped Monaco 0.57.0 linked-editing
compatibility guard in `monaco-compat.js`. That pinned contribution's two delayed
promises otherwise reject without handlers during cancellation/disposal. The
guard observes those promises only; it preserves linked editing and reports
non-cancellation failures. No global unhandled-error filter is installed. Review
this checked private-field contract and the real-browser teardown regression when
upgrading Monaco, rather than silently accepting a changed vendor shape.

## Performance and validation

Large source models and navigation lists keep viewport DOM bounded. Text document
indexes apply incremental UTF-16 changes and semantic/reference work runs in the
language worker. Requests carry cancellation and snapshot checks. External pull
diagnostics are debounced, limited to two concurrent requests, and retry
server-requested cancellation at most three times with backoff. Result snapshots
are invalidated when inter-file dependencies open, change or close.

```sh
npm run test:advanced-editor
npm test
npm run test:browser:advanced-editor
VB6_TEST_TRANSPORT=file npm run test:browser:advanced-editor
VB6_BROWSER=firefox npm run test:browser:advanced-editor
VB6_BROWSER=webkit npm run test:browser:advanced-editor
```

Install the Python Playwright package and the requested browser binaries before
browser tests. HTTP is the default transport. CI builds from pinned dependencies
and runs HTTP/file acceptance for Chromium, Firefox and WebKit in
`.github/workflows/xaml.yml`. `VB6_TEST_TRANSPORT=memory` explicitly exercises the
rebuilt offline HTML via `set_content` in constrained environments; its labelled
result is **not** HTTP or file-delivery acceptance.

The browser suite tests strict opt-in, selection/history, Unicode typing,
multicaret/snippets, worker navigation, minimap/folding, breakpoint/execution
coordinates, read-only state, XAML/designer undo, stale edits, disconnect/reconnect,
project replacement, Peek, rename, superseded startup, symbol/hierarchy tools,
split panes, actual paused-frame tips and pending linked-editing teardown. Its
100,001-line fixture asserts bounded visible DOM, lexical reindexing and UTF-16
scanning. Recorded synchronous programmatic edit-and-sync times are not keystroke
latency, GPU frame time, FPS or a universal hardware performance guarantee.

Keep generated reports in ignored `reports/advanced-editor/` or CI artifacts.
Extend protocol tests under `tests/advanced-editor-*.test.mjs` and behavioral
browser acceptance whenever adding a capability, changing ownership or upgrading
the pinned editor.
